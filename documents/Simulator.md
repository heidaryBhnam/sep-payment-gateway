# شبیه ساز محلی پرداخت

با توجه به اینکه سیاست سازمانی شرکت سپ این است که راهکاری جهت تست در مرحله توسعه ارائه نمیدهد، و توسعه دهندگان نیاز دارند تا در مرحله توسعه شرایط حداقل را جهت تست کد های پیاده سازی شده خود داشته باشند یک سیستم شبیه سازی سرویس درگاه پرداخت سپ پیاده سازی شد. در ادامه با جزئیات این سرویس بیشتر آشنا خواهیم شد.
شبیه ساز برای تست محلی (Local) جریان پرداخت ساخته شده است و هیچ تراکنش واقعی انجام نمی دهد.

## اجرا

در ریشه پروژه اجرا کنید:

```bash
npm run simulator
```

آدرس پیش فرض شبیه ساز `http://127.0.0.1:4100` است. برای تغییر پورت:

```bash
set SEP_SIMULATOR_PORT=4200
npm run simulator
```

سپس gateway را به همان آدرس وصل کنید:

```javascript
const gateway = createSepPaymentGateway({
  SEP_TERMINAL_ID: "123456",
  SEP_BASE_URL: "http://127.0.0.1:4100",
})
```

## سناریوها

صفحه پرداخت شبیه ساز این گزینه ها را نمایش می دهد:

- پرداخت موفق
- پرداخت رد شده
- لغو توسط مشتری
- منقضی شدن پرداخت
- کارت نامعتبر
- موجودی ناکافی
- خطای ارتباطی

بعد از انتخاب سناریو، شبیه ساز به `RedirectURL` فاکتور برمی گردد و پارامترهای `State`، `StateDescription`، `RefNum`، `ResNum` و `Token` را اضافه می کند.

برای سناریوی موفق، `verifyPayment` و سپس `reversePayment` موفق هستند. برای سناریوهای ناموفق، تایید تراکنش با خطا رد می شود. تایید با `TxnRandomSessionKey` اشتباه نیز رد می شود و reversal دوم یک خطای «قبلا برگشت داده شده» ایجاد می کند.

این شبیه ساز وضعیت ها را فقط در حافظه نگه می دارد و با خاموش شدن سرور پاک می شوند.
